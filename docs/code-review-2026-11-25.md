## 2. 문제점 (심각도순)

### 높음 — 릴리스 전 수정 권장

**H1. 실제 공고 수집 실패 시 가짜(샘플) 공고가 실제 인박스에 섞임 [검증]**
- 위치: `app/api/routes_bids.py` `sync_bids` (g2b·seis·bizinfo 3곳 동일), `frontend/src/lib/api.ts` (`use_demo_if_no_key: true` 고정)
- API 키가 **설정된** 상태에서 일시 장애(503 등)가 나면 `except` 후 데모 분기로 넘어가 샘플 공고를 저장하고, 보고서에는 "API 키 미설정 — 샘플 공고 시드 반영"이라고 표시. 실제 오류 메시지는 사라짐.
- 샘플 공고는 실제와 같은 공고번호 형식·실제 기관명·g2b.go.kr 링크·며칠 뒤 마감일을 가지며, DB에 데모 표시 컬럼이 없어 인박스에서 구분 불가 → 존재하지 않는 공고를 승인·제안서 작성할 위험.
- 수정: 키가 있을 때 실패하면 데모로 대체하지 말고 오류를 보고. `bids.is_demo` 컬럼 + 목록 배지 추가.

**H2. HWPX 지정 양식 패치가 엉뚱한 문단을 덮어씀 [검증]**
- 위치: `app/documents/hwpx_engine.py` — 파서는 빈 문단 포함 모든 본문 문단을 세고(`body_para_idx`), 패치는 텍스트 있는 문단만 셈(`body_idx`).
- 재현: 문단 [제목, (빈 줄), "1. 사업 개요 (여기에 작성)", "2. 아래 서명란은 수정하지 마십시오"] → 슬롯 `p2`를 패치하면 입력란은 그대로이고 **"서명란은 수정하지 마십시오" 문단이 AI 본문으로 교체**됨.
- 수정: 두 함수가 같은 기준(빈 문단 포함)으로 세도록 통일하고 회귀 테스트 추가.

**H3. 나라장터 수집이 윈도우·분류당 50건에서 잘림 [코드]**
- 위치: `app/collectors/g2b.py` `fetch_g2b_bids(max_pages=1, num_of_rows=50)` — `/sync`가 기본값 사용.
- 7일 동안 용역 공고가 50건을 넘으면 나머지는 조용히 누락(사용자에게 표시 없음).
- 수정: `totalCount` 기준 페이지네이션(일일 쿼터 범위 내), 잘린 경우 보고서에 표시.

**H4. 단가 미등록 모델은 월 예산 상한에 집계되지 않음 (P1 보완 필요) [검증]**
- 위치: `app/ai/llm_client.py` `record_token_usage` — 단가 없으면 비용 0원·`pricing_missing=1`로 기록.
- 재현: 예산 1,000원, 미등록 모델로 입력 1천만·출력 4백만 토큰 사용 → 집계 0원, 차단 안 됨.
- 수정: Live 호출인데 단가가 없으면 보수적 대체 단가(가장 비싼 등록 단가)로 집계하거나 예산 설정 시 호출 자체를 차단·경고.

**H5. LLM 점수 형식 오류 하나로 공고 수집 전체가 실패 [검증]**
- 위치: `app/ai/scoring.py` `int(match.get("score", ...))` (예외 처리 없음)
- `"85.5"`, `"85점"`, `null` 응답 시 `ValueError/TypeError`가 `/api/bids/sync` 전체를 500으로 실패시켜 수집한 공고도 저장되지 않음.
- 수정: 안전한 숫자 파싱(실패 시 휴리스틱 점수 유지).

### 중간

**M1. 대시보드 "공고 수집" 중복 실행 방지 없음 [코드]** — 버튼 비활성화·잠금이 없고 서버 `/api/bids/sync`에도 작업 가드 없음. 연타 시 공공 API 쿼터와 (Live) 채점 LLM 호출이 중복. P0 때 누락된 경로.

**M2. 지역 제한 2글자 비교 오류 [검증]** — `rule_filter.py`·`rfp_analyzer.py`의 `comp_region[:2]` 비교로 경상남도↔경상북도, 충청남·북도, 전라남·북도가 같은 지역으로 통과. 업로드 RFP의 Go/No-Go는 지역 메타가 없어 항상 "전국" 처리.

**M3. 사업계획서 내보내기 제목이 내부 키로 출력 [검증]** — DOCX/MD/HWPX(재생성) 제목이 `problem`, `scaleup`, `t0r1c1` 등. DOCX는 `####` 제목 미지원(문자 그대로 출력), `font.name`만 설정해 한글(East Asian) 글꼴 미적용 가능.

**M4. 진흥원·기업마당 수집 데이터 견고성 [코드]**
- SEIS `bid_no` 대체값이 목록 순번(`SEIS-{idx}`) → 다른 날 다른 공고가 같은 ID로 덮어써지고 이전 승인 상태를 물려받음.
- `int(supportAmt)`가 쉼표 금액에서 실패 → 수집 전체 실패(→ H1의 데모 대체로 이어짐).
- 기업마당 `deadline`에 접수 기간 범위 문자열이 들어감. 첨부 저장 폴더명이 외부 값(`bid_no`, 제목 일부)으로 만들어지고 다운로드 크기 제한 없음.

**M5. 공공 API 일일 쿼터는 기록만 하고 강제하지 않음 [코드]** — `increment_quota`만 있고 호출 전 잔여량 확인 없음.

**M6. 문서 업로드 오류가 500으로 노출 [코드]** — `HwpxSecurityError`·손상 파일 등 `ValueError`가 처리되지 않아 사용자는 "요청 실패 (500)"만 봄. 400과 사유 메시지로 변환 필요.

**M7. 릴리스 재현성 [코드]** — `requirements.txt`가 하한만 지정(`python-hwpx>=2.0`인데 코드는 7.x API 사용), 잠금 파일 없음. CI는 Python 3.12, 로컬은 3.13. 동결 exe에서 `google-genai`(함수 내 지연 import)가 포함되는지 CI 스모크 테스트가 확인하지 않아 Live 모드 동작이 검증되지 않음.

**M8. 기본 프로필 데이터 [코드]** — 가상 회사((주)함께자람, 사업자번호 등)가 기본값이라 사용자가 수정하지 않으면 제안서·사업계획서에 가상 회사 정보가 들어감. 또한 "예비사회적기업"인데 `is_certified_social: True`라 수의계약 특례가 적용됨.

### 낮음

- `load_config()`가 호출마다 `seed_defaults()`(파일 확인·프롬프트 폴더 glob) 실행 — 요청당 수십 회. 캐시 권장.
- 토큰 부트스트랩(`resolveSessionToken`) 경쟁: 동시 호출마다 450ms 대기, PyWebview 준비가 늦으면 첫 요청이 빈 토큰으로 403.
- 모델 목록 조회 시 API 키를 URL 쿼리(`?key=`)로 전송 — 헤더(`x-goog-api-key`) 권장.
- 공공 API 오류 판별 `">22<" in text`는 XML 응답에서 오탐 가능(현재 JSON 요청이라 영향 작음).
- RFP 시나리오 판별이 "목차" 단어만으로 A 처리, 총 분량 6,500자 고정(공고의 페이지 제한 미반영).
- `MarkdownPreview` 목록 항목이 `<ul>` 없이 `<li>`로 렌더링.
- CI: WebView2 부트스트래퍼를 서명·해시 확인 없이 다운로드, setup.exe 코드 서명 없음(SmartScreen 경고), Actions가 SHA가 아닌 태그로 고정.
